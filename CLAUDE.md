# CLAUDE.md: Phiraya (`phiraya` branch)

This branch holds **Phiraya** only. It is due to move to its own private repo
(`phiraya`, default branch `main`) once the owner creates it. It is an orphan branch with no shared history with
LEXIS, which lives on the other branches of this repo. Read `phiraya/README.md` for
status and open items, and `phiraya/BRIEF-FOR-OTHER-AGENTS.md` for the rules every
tool must follow.

## What Phiraya is

Client communication for clinics, premium services and medium-sized businesses across
Thailand and the West: outreach, calls, bookings, follow-up, in English and Thai.
Line: "Every client connection, handled." Tone: warm, capable, discreet, responsive.

## Hard rules (owner decisions; never override)

- **Name:** Phiraya, Thai **พิรยา**. Never "Phitara" or "Piyara".
- **LEXIS is a separate business** (English tutor, learnwithlexis.com). Never touch LEXIS
  branches, code, avatars, Stripe or Supabase from Phiraya work, and never put Phiraya
  material on LEXIS. Commit only to the `phiraya` branch.
- **Never mention AI**, bots, automation or voice synthesis anywhere public (site copy,
  captions, scripts, client-visible file names, HTML comments in shipped pages).
- **Never claim she is human**, a "real person" or "live staff". If a caller sincerely asks,
  she offers to connect them to staff and does not say she is a person.
- **No health or medical advice.** For clinics she offers bookings and answers.
- Label generated videos and chats as **demos**, never "live" or "real".
- Don't send emails, post publicly, buy domains, publish the site or contact anyone
  without the owner's approval. Ask before spending generation credits beyond a small,
  requested job, and report what was spent.
- Never commit or paste API keys, tokens or signed/expiring URLs (e.g. OSS or GCS links
  with `Signature=`/`Expires=`). Download assets into the repo instead.

## Commands

```bash
# Rebuild the site after editing src.html or an asset (run from phiraya/)
python3 -I site/build.py site
# Check no placeholder survived
grep -c "__[A-Z]*__" site/index.html          # must print 0
# Smoke test (from phiraya/site; needs playwright). Fails on page errors, horizontal
# overflow, leftover tokens, or banned wording (AI, human, Phitara) in page copy.
PW_CHROMIUM=/opt/pw-browsers/chromium_headless_shell-1194/chrome-linux/headless_shell node tests/smoke.mjs

# Background cut-out for a new grey-backdrop portrait (needs pillow numpy scipy)
python3 -I site/cutout.py in.jpg out.png

# Re-render the promo (from phiraya/promo/; needs Node 22, ffmpeg, ffprobe)
HYPERFRAMES_BROWSER_PATH=/opt/pw-browsers/chromium_headless_shell-1194/chrome-linux/headless_shell \
  npx hyperframes@0.8.114 render -o out.mp4
```

Adding an inlined asset means adding its token to the list in `build.py` (MIME is
chosen by extension: webp, jpg, mp4, mp3).

## Site conventions (`site/src.html`)

- **One self-contained file, no external libraries or CDNs.** Fonts, portraits, video and
  audio are inlined by `build.py`. Plain ES5-style JS inside one IIFE, `'use strict'`.
- **Brand tokens** in `:root`: ink `#07090C`/`#0E1116`, gold `#C9A45C`, gold-2 `#E7CC8F`,
  ivory `#F4EFE6`. Fonts: Cormorant Garamond (headings, `.serif`) and Inter (body).
  Don't introduce a new palette or fonts.
- **Background field:** a live nonlocal Kuramoto oscillator simulation on a torus.
  `dθ/dt = ω + K·Σ G·sin(θj − θi − α)`, coupling via repeated periodic box blur, rendered
  as isophase lines. Defaults `R=3, K=3, α=0.75, spread 0.004, 4 vortex pairs`; they can be
  overridden by URL params (`?R=&K=&a=&sp=&nv=&seed=`) for tuning. Grid capped at 42k
  cells. Pointer = pacemaker (target waves), tap = vortex pair, pinch / ctrl+wheel = zoom,
  scroll morphs α. Pauses when hidden and slows under `prefers-reduced-motion`.
- **Avatar:** a 48-oscillator mean-field Kuramoto ring around her portrait; hover raises K.
- **Call demo:** silent looping video plus `call-voice.mp3` started together; the transcript
  `<p data-t0 data-t1>` times must match the audio (seconds). Update them whenever the voice
  file changes.
- `main` is `pointer-events:none` so the field receives input; give interactive elements
  `a`, `button`, `.interactive` or `canvas.av`.
- Contact buttons are `.placeholder` (disabled) with `TODO(owner)` until real email, LINE ID,
  WhatsApp and booking link exist.
- Mobile: no horizontal scroll at 390px (`html{overflow-x:hidden}`, hero `overflow:hidden`);
  check both layouts after layout changes.

## CI

`.github/workflows/phiraya-site.yml` runs on pushes and PRs to `main` (the planned
standalone Phiraya repo, so it never runs in the LEXIS repo). It rebuilds the site, fails if
the committed `site/index.html` is stale, and runs `tests/smoke.mjs`. Always commit the
rebuilt `index.html` together with `src.html` changes.

## Commits

- Branch `phiraya` only; push with `git push -u origin phiraya`.
- Message style: `Phiraya: <what changed>` or `Phiraya site: <what changed>`, then a short
  body explaining why. Attribution lines as the session requires.
- No PRs: the branch shares no history with the default branch.

## Review standards (owner's preferences)

- **Important** only for things that break behaviour, leak data or block a rollback: wrong
  logic, queries not scoped to the caller's tenant, PII in logs or errors, migrations that
  aren't backward compatible. Style and naming are Nit at most.
- At most five Nits per review ("plus N similar items" beyond that). If everything is a Nit,
  lead with "No blocking issues."
- Don't report what CI enforces (lint, format, types), generated files (`src/gen/`,
  `site/index.html`), `*.lock` files, or test-only code that intentionally breaks rules.
- Always check: new API routes have an integration test; logs contain no emails, user IDs
  or request bodies; every database query is scoped to the caller's tenant.
